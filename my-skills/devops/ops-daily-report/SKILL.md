# 运维日报生成

## 企微投递门控（最高优先级）

本 skill 通常由 Hermes cron 执行并投递到企微。为减少无效通知，必须先完成异常判定，再决定输出内容。

### 输出决策
- 若没有真实异常：最终响应必须精确输出 `[SILENT]`，不要输出日报标题、表格、解释、前后缀或任何其它字符。
- 若存在至少 1 条真实异常：按下方固定格式输出完整日报，并在“异常告警”中列出异常。

### 真实异常定义
以下情况视为真实异常，会触发完整日报投递：
- 服务状态为 `down` 或输出为 🔴（Tailscale VPN 除外，见下方排除规则）。
- 任务状态为 `failed` 或 `missed`。
- 关键数据质量为 🔴，包括股票 EOD、期权链、宏观日历等。
- 数据接口、dashboard 工具或期权链汇总调用报错。
- 昨天是交易日时，期权链无数据或 `avg_per_symbol <= 0`。
- 耗时异常超过本 skill 设定阈值（须结合当日数据量判断，见耗时异常检测规则）。

以下情况不视为真实异常，不应单独触发企微投递：
- 所有服务、任务和数据均为 🟢。
- 仅有正常统计、成功数量、绿色状态或周末/休市跳过项（⏭）。
- 任务状态为 `pending` 或 `running`，且按调度时间尚未到应完成时间。
- **Tailscale VPN 状态为 🔴**：Tailscale 偶发断连属正常现象，不计入异常，服务状态表中照常展示 🔴，但不写入异常告警、不触发投递。

### 执行顺序
1. 先获取服务、任务、数据同步质量、期权链和宏观日历信息。
2. 根据“真实异常定义”汇总异常列表。
3. 若异常列表为空，直接输出 `[SILENT]` 并停止。
4. 若异常列表非空，继续按固定输出格式生成日报。

## 判定规则

### 服务状态
- up = 🟢, down = 🔴

### 任务状态统计
- done = ✅ 成功
- failed = ❌ 失败
- pending/running = ⏳ 待运行

### 耗时异常检测
使用 `get_task_duration_history(project_id, task_id, limit=30)` 获取历史耗时

**核心原则：耗时必须结合当日数据量判断，不能仅凭倍数触发异常。**

**判断步骤**：
1. 获取当日任务耗时 `duration` 和历史平均 `avg`
2. 计算倍数 `multiplier = duration / avg`
3. 若 `multiplier` 超过下方阈值，**继续**：
4. 从 `result_detail` 获取当日处理数据量（`ok` + `failed` 之和）
5. 从历史记录中估算历史平均数据量
6. 若当日数据量 ≥ 历史平均数据量 × 1.5，则耗时增长可由数据量解释，**不算异常**
7. 若当日数据量与历史相近，耗时仍超阈值，**才记录为耗时异常**

**阈值（仅作为初筛，须通过数据量验证）**：
| 任务类型 | 初筛阈值 |
|----------|----------|
| 数据同步类 | > 历史平均 × 3 |
| 扫描类 | > 历史平均 × 2.5 |
| 分析类 | > 历史平均 × 2.5 |

**异常记录格式**：
| 耗时异常 | {task_name} | {duration}s vs 平均{avg}s ({multiplier}×)，当日数据量与历史相近 |

### 期权链数据完整性
使用 `get_options_chain_summary(date=昨天)` 直接获取聚合结果

**工具**：`dashboard_options_chain_summary(date=昨天)`

**返回字段**：
- `market`：市场（US / HK）
- `symbol_count`：已同步标的数 → 填"标的数"列
- `avg_per_symbol`：平均单标的合约数 → 直接填"平均合约数"列

**状态判定**：
- avg_per_symbol > 0 = 🟢
- 无数据且昨天是交易日（周一至周五）= 🔴
- 无数据且昨天是周末（周六/周日）= ⏭ 跳过（休市，不计入异常）
- 接口报错 = 🔴

### 数据完整率
- ≥ 95% = 🟢
- 90-95% = 🟡
- < 90% = 🔴

## 执行步骤

1. 获取当前北京时间日期
2. 计算昨天日期：YYYY-MM-DD
3. 调用 `dashboard_summary` 获取服务状态
4. **遍历 `services` 数组中的所有服务**，输出服务状态表（不是只输出模板中的示例）
5. 调用 `dashboard_task_status` date=昨天日期 获取任务详情
5. 解析任务数据，统计各项目 success/failed/pending 数量
6. 解析 result_detail 获取同步数量 {"ok": N, "failed": M}
7. **耗时异常检测**：
   - 对每个已完成任务，调用 `get_task_duration_history` 获取历史平均
   - 对比当日耗时，超阈值则记录异常
8. **期权链数据**：
   - 先判断昨天是否是交易日（weekday() 0-4 = 交易日，5=周六/6=周日 = 休市）
   - 若昨天是休市日：期权链整行填 "—"，标 ⏭，不做异常检测
   - 若昨天是交易日：调用 `dashboard_options_chain_summary(date=昨天日期)`，`symbol_count` → 填入"标的数"列，`avg_per_symbol` → 填入"平均合约数"列（直接使用返回值，例：193.6）
10. **其他数据完整性**：
    - 宏观日历：从昨天任务数据中找 `macro_indicators_daily`
      - 状态为 `done`（无论 result_detail 是否为 null）→ 数量填 result_detail.ok；若 result_detail 为 null 或缺少 ok 字段，**必须填 9**，标 🟢
      - 注意：`result_detail=null` 不代表失败，done 就是成功，**严禁把 done 标为 🔴**
      - 状态为 `failed` / `missed` 或任务不存在 → 数量填 0，标 🔴
      - 状态为 `pending` → 任务未到时间，数量填 —，标 ⏳
11. 汇总异常，按固定格式输出日报

## 禁止
- 不要输出思考过程或分析说明
- 不要添加任何报告正文以外的文字
- 不要添加未定义的章节
- 不要在数值位置显示"充足"、"-"等非数字，必须是具体数字
- 不要改变 emoji 含义

## 输出要求
- 直接输出报告正文，第一行必须是 `📊 运维日报（YYYY-MM-DD）`
- 不要任何前缀说明（如 "Now I have..."、"以下是..." 等）
- 不要任何后缀总结
- 期权链"平均合约数"列必须填 total_contracts÷symbol_count 的计算结果（保留1位小数），不是"充足"、"-"等非数字
- 有异常时要检测耗时异常并列入异常告警
